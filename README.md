# LayerFox AI — Upload-ready starter

واجهة عربية لتقسيم صور الأنمي إلى طبقات، مع خادم FastAPI قابل للنشر على Render.

## مهم قبل النشر
هذا مشروع مرتب وجاهز للرفع، لكن **تقسيم الصورة بالذكاء الاصطناعي لن يعمل حتى تربط خدمة نموذج فعلية**. لم أضع تكاملًا وهميًا أو أزعم أن XML الخاص بـ Alight Motion جاهز. إعدادات نموذج See-through/Gradio تختلف حسب الـ Space، لذلك يلزم التحقق من اسم الدالة والمدخلات أولًا.

## الملفات
- `index.html` — واجهة الموقع.
- `backend/app.py` — خادم API.
- `backend/requirements.txt` — المكتبات.
- `render.yaml` — إعداد نشر Render.

## النشر على GitHub من الهاتف
GitHub لا يفك ضغط ZIP تلقائيًا. فك الضغط أولًا، ثم ارفع **محتويات** المجلد إلى المستودع مع الحفاظ على بنية `backend/`.
إذا كان رفع المجلدات صعبًا، أنشئ الملفات التالية داخل GitHub يدويًا، لكن الصق محتويات كل ملف من الأرشيف.

## النشر على Render
1. ارفع الملفات إلى مستودع GitHub.
2. في Render اختر New → Blueprint، ثم اربط المستودع الذي يحتوي `render.yaml`.
3. بعد النشر افتح رابط الخدمة.
4. الصفحة الرئيسية تعرض الواجهة. `/health` يفحص الخادم.

## تفعيل نموذج الذكاء الاصطناعي
في Render → Environment أضف:
- `HF_SPACE_ID` — معرّف Hugging Face Space الصحيح.
- `HF_API_NAME` — اسم endpoint الصحيح كما يظهر في `Client(...).view_api()`.

لا تخمّن قيمة `HF_API_NAME`. إذا بقيت فارغة، سيعرض الموقع رسالة واضحة بدل اختلاق نتيجة.

## حدود النسخة
- الواجهة والخادم جاهزان كبنية أولية.
- لا يوجد حتى الآن تصدير XML حقيقي لـ Alight Motion.
- لا تضع كلمات مرور أو مفاتيح API في ملفات GitHub؛ استخدم Environment Variables.
